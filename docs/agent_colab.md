# 에이전트용 지침: 코랩에서 01·02 노트북 실행

사용자의 PC 크롬 브라우저에서 구글 코랩 노트북 두 개를 차례로 실행한다. 계산은 구글 GPU에서 돌고, 이 PC는 탭을 열어 두는 역할만 한다.
**유닛(돈)이 드는 작업이므로 아래에 적힌 것 외에는 하지 않는다.**

## 하지 말 것

- 유닛 구매, 요금제 변경, 결제 화면 진행
- 노트북 코드 셀 수정 (아래에 적힌 경우 제외)
- 토큰·비밀번호 입력, 노트북 공유 설정 변경
- 적힌 것과 다른 GPU 선택 (01은 A100만, 02는 L4만)
- 에러가 난 런타임을 켜 둔 채로 두기 (켜져 있으면 아무것도 안 해도 유닛이 나간다)

## 시작 전 확인

1. 크롬이 사용자의 구글 계정으로 로그인되어 있다.
2. 윈도우 절전 모드: 설정 → 시스템 → 전원 → 절전 모드 전환 "안 함".
3. 크롬 설정 → 성능 → 메모리 절약 → "항상 활성 상태로 유지할 사이트"에 `colab.research.google.com` 추가.
4. 남은 유닛 확인: 코랩 오른쪽 위 계정 메뉴 또는 https://colab.research.google.com/signup 의 사용량. **22유닛 미만이면 시작하지 말고 사용자에게 알린다.**

## 1단계: 01 노트북 (A100, 약 1.5시간, 약 14~16유닛)

1. 이 주소를 연다: https://colab.research.google.com/github/b1bibig/Cfinetune/blob/ccr-a463bea6-bpbyrh/notebooks/01_calibrate.ipynb
2. 메뉴 **런타임 → 런타임 유형 변경** → 하드웨어 가속기 **A100 GPU** 선택 → 저장.
   - 80GB/40GB를 고르는 옵션이 보이면 **80GB**.
3. 메뉴 **런타임 → 모두 실행**.
4. 뜨는 창 처리:
   - "경고: 이 노트북은 Google에서 작성하지 않았습니다" → **무시하고 계속하기**
   - "Google Drive에 연결" → **Google Drive에 연결** → 사용자 계정 선택 → **모두 허용/계속**
5. GPU 확인 셀(`nvidia-smi` 나오는 셀) 결과를 본다.
   - `GPU 메모리 80GB` 근처가 나오면 정상.
   - `AssertionError: 런타임 > 런타임 유형 변경에서 A100 (80GB) 또는 G4 를 고르세요`가 나오면 40GB짜리를 받은 것.
     → **런타임 → 런타임 연결 해제 및 삭제** → 2번부터 다시. 3번 시도해도 같으면 중단하고 사용자에게 알린다.
   - "GPU를 사용할 수 없음" 같은 창이 뜨면 10분 기다렸다가 다시. 3번 실패하면 중단하고 알린다.
6. 이후에는 지켜보기만 한다. 정상 진행 표시:
   - `[ko] 0/512`, `[ko] 128/512` … → `재구성 오차 최대 0.0xxx` → `저장: .../stats-ko.json`
   - 그래프 1장 출력
   - llama.cpp 빌드 (10~15분, 컴파일 로그)
   - 원본 BF16 변환 (`Writing ...` 진행 막대, 10~20분)
   - 속도 측정 → `답변 8개: 1개당 ... Wh` 줄과 `저장: .../original-BF16@A100-80GB.json`
   - 마지막 셀이 런타임을 끄면서 "런타임 연결이 끊겼습니다" 류의 표시
7. 끝난 뒤 확인 (구글 드라이브 웹에서):
   - `내 드라이브/cfinetune/results/calib/stats-ko.json` 있음
   - `내 드라이브/cfinetune/results/bench/original-BF16@A100-80GB.json` 있음

### 01에서 문제가 생기면

- 빨간 에러(Traceback)가 나고 실행이 멈췄다 → 화면을 캡처하고, **런타임 → 런타임 연결 해제 및 삭제**를 누른 뒤 사용자에게 알린다. 다시 실행하지 않는다.
- `재구성 오차 ... 관측기 계산이 실제 모델 출력과 맞지 않음` 에러 → 위와 같이 캡처·종료·보고.
- 30분 넘게 새 출력이 전혀 없다 (진행 막대·로그가 멈춤) → 캡처해서 보고. 런타임은 끄지 말고 사용자 판단을 기다린다.
- 브라우저가 "연결 끊김"을 표시하면 **다시 연결**을 누른다. 실행 중이던 셀이 계속 돌고 있으면 그대로 둔다.

## 2단계: 02 노트북 (L4, 약 3.5~4시간, 약 6~7유닛)

01이 정상으로 끝난 뒤에만 시작한다 (01 결과 파일이 있어야 돌아간다).

1. 시작 전 드라이브 남은 용량 확인 (drive.google.com 왼쪽 아래 "저장용량"). **15GB 미만이면 시작하지 말고 사용자에게 알린다.**
2. 이 주소를 연다: https://colab.research.google.com/github/b1bibig/Cfinetune/blob/ccr-a463bea6-bpbyrh/notebooks/02_prune_quantize_eval.ipynb
3. **런타임 → 런타임 유형 변경** → **L4 GPU** → 저장.
4. **런타임 → 모두 실행**. 경고·드라이브 연결 창은 1단계처럼 처리.
5. GPU 확인 셀에서 `L4`, 메모리 22~24GB 근처가 나오고 디스크(`df`) 남은 공간이 100GB 이상인지 본다. 100GB 미만이면 캡처해서 보고 (진행은 계속).
6. 정상 진행 표시: 변형마다 `$ python ... convert_hf_to_gguf.py` → `llama-quantize` → `객관식 0/3008 …` → `PPL[ko] = …` → `답변 8개: …` → `드라이브에 결과 저장함`.
   변형 순서: original(Q6_K, Q4_K_M) → ko-k48(Q6_K) → ko-k32(Q6_K, Q4_K_M, Q3_K_M, Q2_K).
7. 마지막 셀이 런타임을 끈다.
8. 끝난 뒤 드라이브 확인:
   - `cfinetune/results/eval/` 에 json 7개
   - `cfinetune/results/bench/` 에 `...@L4.json` 7개
   - `cfinetune/gguf/original-Q4_K_M.gguf` (약 13GB)

### 02에서 끊기거나 멈추면

02는 끝난 변형을 건너뛰도록 되어 있다. 연결이 끊겨 런타임이 사라졌으면 2번부터 다시 하면 남은 변형만 이어서 한다 (처음 20~30분은 원본을 다시 받느라 걸린다).
빨간 에러로 멈췄으면 캡처 → 런타임 연결 해제 및 삭제 → 보고.
